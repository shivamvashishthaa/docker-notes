## 1. Why Do We Need Docker Storage?

Containers are designed to be **stateless** and **ephemeral**. 
*   If you stop and remove a container, the data inside it is **permanently lost**.
*   If you update your application code and create a new container, the old data won't be there.

**Solution:** We need a way to store data **outside** the container's writable layer, so it persists even if the container is deleted. This is called **Binding Container Data to Host Machine**.

---

## 2. Types of Mounts in Docker

Docker provides three main ways to mount storage:

1.  **Volumes:** Managed by Docker (stored in `/var/lib/docker/volumes/`). **Best for production.**
2.  **Bind Mounts:** Maps any host directory to a container directory. **Best for development.**
3.  **tmpfs Mounts:** Stores data in RAM (memory). **Best for sensitive data.**

---

## 3. Docker Volumes (Deep Dive)

Volumes are the **preferred mechanism** for persisting data generated by and used by Docker containers.

*   **Location:** `/var/lib/docker/volumes/` (on Linux).
*   **Management:** Fully managed by Docker.
*   **Portability:** Can be easily backed up, restored, and migrated.
*   **Use Case:** Database storage (MySQL, PostgreSQL), application logs, etc.

### Creating a Volume
```bash
docker volume create <volume_name>
# Example: docker volume create mysql-data
```

### Inspecting a Volume
```bash
docker volume inspect <volume_name>
# Example: docker volume inspect mysql-data
```
- This will show you the mount point on the host machine.

### Using a Volume in a Container

```bash
docker run -v <volume_name>:<container_path> <image_name>
# Example: docker run -v mysql-data:/var/lib/mysql mysql
```

---

### Using a Bind Mount

```bash
docker run -v <host_path>:<container_path> <image_name>
# Example: docker run -v /home/user/app:/app my-app
```

> 💡 Note: You can also use --mount flag instead of -v for more explicit syntax:

```bash
docker run --mount type=bind,source=/home/user/app,target=/app my-app
```
---

## 5. tmpfs Mounts

 tmpfs mount stores data in the host machine's memory (RAM) instead of the filesystem.

- Location: RAM.

- Persistence: Data is lost when the container stops.

- Use Case: Storing sensitive data (passwords, tokens) that you don't want to write to disk.

### Using tmpfs
```bash
docker run --tmpfs /app/temp my-app
```
---

## 6. Volumes vs Bind Mounts (Comparison)

| Feature | Permission | Meaning |
| ------- | ---------- | ------- |
| Managed By  | Docker | User (You) |
| Location  | `/var/lib/docker/volumes/` | Anywhere on Host |
| Portability | High (Easy to backup/migrate) | Low (Depends on host path) |
| Use Case  | Production, Databases | Development, Code Editing |
| Performance | High | High |
| Syntax | `-v volume_name:/path` | `-v /host/path:/path` |

---

## 7. Volume Management Commands

```bash
# Create a volume
docker volume create <volume_name>

# List all volumes
docker volume ls

# Inspect a volume (see mount point, driver, etc.)
docker volume inspect <volume_name>

# Remove a specific volume
docker volume rm <volume_name>

# Remove all unused volumes (DANGER: Data loss!)
docker volume prune
```

## 8. Real-World Example: MySQL with Volume

Let's see how to run a MySQL container with a volume to persist data.

### Step 1: Create a Volume
```bash
docker volume create mysql-data
```

### Step 2: Run MySQL Container with Volume

```bash
docker run -d \
  --name mysql-container \
  -e MYSQL_ROOT_PASSWORD=root \
  -e MYSQL_DATABASE=myapp \
  -v mysql-data:/var/lib/mysql \
  -p 3306:3306 \
  mysql:8.0
```

- `-v mysql-data:/var/lib/mysql` maps the volume to the MySQL data directory inside the container.

- Even if you delete the `mysql-container`, the data will remain in the `mysql-data` volume.

### Step 3: Verify Data Persistence

1. Stop and remove the container:

```bash
docker stop mysql-container
docker rm mysql-container
```

2. Run a new MySQL container using the same volume:

```bash
docker run -d --name mysql-new -e MYSQL_ROOT_PASSWORD=root -v mysql-data:/var/lib/mysql -p 3306:3306 mysql:8.0
```

3. Connect to the new container and check if your database (myapp) still exists. It will!
